## Summary
The failure path of the manual retro would crash, and the doctor venv check fails on every real venv. Tests required by the acceptance criteria are also missing: none for test_verbs.py, and none for retro's failure path or exact output and lock refusals in the CLI.

## Findings
- correctness_review at squatch/__main__.py:193: `_retro` returns `EXIT_TICKET`, but that name is never imported or defined in squatch/__main__.py. The import list at line 50 brings in only EXIT_OK, EXIT_REFUSED, PipelineFactory, Refusal and Runner from squatch.runner. When a selected run is suppressed or fails, this raises NameError instead of printing `retro: no report committed; inspect status and the Suggestion Box` and exiting 1. No test covers this path, so the suite stayed green. (paved road: Import the exit-1 constant from the module that owns the exit classes, or define it there. Then add the missing failure-path test (see the next findings).)
- correctness_review at squatch/doctor.py:110: `_venv` calls `.resolve()` on `sys.executable`, and that follows the venv's interpreter symlink out of the checkout. In this repo, `.venv/bin/python` resolves to `~/.local/share/uv/python/cpython-3.14.6-.../bin/python3.14`, so `expected not in (actual, *actual.parents)` is always true. Every real `squatch doctor` run therefore reports FAIL venv and exits 2, even when it is running from the checkout `.venv`. (paved road: Judge the venv by `sys.prefix`, which should resolve to `<repo>/.venv`. Alternatively, compare the unresolved absolute `sys.executable` path against `<repo>/.venv`. Add a test in which the interpreter is a symlink inside `.venv` that points outside it.)
- correctness_review at squatch/__main__.py:185: The GitError check scans every `retro_failed` signal in the journal with the same `window_boundary`, including ones written before this invocation. Suppose an earlier drain or manual run on the same window failed with GitError, and this forced run then fails or is suppressed for some other reason. It gets misreported as a git refusal with exit 2 instead of the contract's exit-1 message. This is uncertain: it depends on whether a boundary can gain a second retro_failed record, but nothing in the code rules that out. (paved road: Only look at events appended during this run, for example by recording the journal length before `retro.run` and scanning after it. Better, have `Retro.run` return or raise the failure class directly so the CLI does not re-derive it from the journal.)
- correctness_review at tests/test_verbs.py: Acceptance criterion 4 is not met. tests/test_verbs.py is not in the diff, so nothing there proves the manual `retro` or provider-free `doctor` dispatch contracts, or that the verb surface is preserved with the two new verbs. (paved road: Extend tests/test_verbs.py to assert that the verb surface includes `doctor` and `retro` and that each dispatches through its contract: retro through the governed Retro path, doctor with no provider or pipeline construction.)
- correctness_review at tests/test_retro.py:241: Acceptance criterion 2 is only partly met. tests/test_retro.py adds only the successful committed-report case. It has no manual no-merge test and no selected-failure test with the exact message and exit 1. The missing failure test is why the EXIT_TICKET NameError went unnoticed. (paved road: Add tests/test_retro.py cases for manual no-merge (exact output, exit 0, no model call, no write) and for a failed or suppressed selected run (exact `retro: no report committed; inspect status and the Suggestion Box` output, exit 1), both through `main(["retro"])` and the governed Retro path.)
- correctness_review at tests/test_cli.py:279: Acceptance criterion 3 is only partly met. The doctor CLI test checks only line prefixes, not the exact operator output. Neither verb has a lock-held refusal test. Retro has no tests for refusal rendering or exit 2 on config, Git, construction or journal failures, and no exit-1 test.
