## Summary
The wrapper is wired into Stages and compose_pipeline, and drain reconciliation is added. But the detector gets double-counted spend and metering guessed from the provider name. Output mutations and cap waits never reach it. The required activation, notify and dormancy-migration tests are missing or only partly done.

## Findings
- correctness_review at squatch/watchdog.py:183: Spend is counted twice. CliClient.call already emits WatchdogEvent(provider, 'start', usd=est_cost_per_call_usd) through on_event (providers.py:367-370). After the call returns, WatchdogLLM.call injects a second synthetic 'start' event with usd=result.usd. For flat-estimate rows each call is charged twice and counted as two starts, which brings soft trips forward. For metered rows the estimate (None) and the actual cost go through two separate start events. (paved road: Remove the synthetic post-call event. Add the metered actual cost only when the row is metered and the stream did not already report it, and never emit a second 'start' for one call.)
- correctness_review at squatch/watchdog.py:166: The metered flag is hardcoded as `provider.name == "claude"` instead of being read from the adapter capability (ADAPTERS[name].reports_cost, as used in providers.py:264). The cost basis is also the max flat estimate across ALL providers, with a made-up 1.0 USD fallback, instead of the serving row's basis as the ticket specifies. It also reads the private Registry._providers. (paved road: Derive provider_reports_metered_usage from ADAPTERS[p.name].reports_cost. Derive the USD basis from the row that serves the request, through a public Registry/config accessor. Drop the invented 1.0 default.)
- correctness_review at squatch/watchdog.py:189: Nothing in production feeds output mutations or provider-cap wait intervals to the detector. observe_mutation and observe_cap_wait are defined, but no call site in stages.py or anywhere else in the diff invokes them. The ticket requires 'separate output-mutation observations through the filesystem seam, and provider-cap wait intervals' to be supplied. (paved road: Wire the Stages filesystem seam's writes into WatchdogLLM.observe_mutation, and the provider-cap wait path into observe_cap_wait (empty when no wait occurs). Prove both in tests/test_watchdog_activation.py.)
- correctness_review at tests/test_watchdog_activation.py:1: Acceptance criteria 1-3 are unmet. The file only calls WatchdogLLM directly with a fake client (the 'direct detector calls are insufficient' / 'test-only binding' rejection case). It never drives real drain or serve composition through the Stages-owned Driver or review. It does not prove that mutations, USD basis or cap waits reach the detector. Also missing: healthy/no-page, fresh-run notification, stuck abort/unwind preservation with the stuck signal body, drain startup and after-dispatch reconciliation, the configured private transport, and the unset-notify status-only warning. (paved road: Add tests that build the pipeline via __main__ drain/serve composition (watchdog bound) with injected process events and clock, run a ticket through implement AND review, and assert each item listed in acceptance criteria 1-3.)
- correctness_review at tests/test_notify.py:200: The ticket requires test_unrelated_signals_and_hold_release_do_not_notify to be migrated unconditionally, adding recognized soft/stuck delivery assertions. That test is left unchanged, and a separate test is added instead. The new test also does not cover unmatched-intent retry: it only checks count dedup and a replay reconcile, with no failed delivery followed by a retry. (paved road: Edit the named test in place: keep the bare {'kind': 'watchdog'} exclusion and add recognized soft/stuck bodies with delivery assertions. Add a failing-transport-then-retry case for the watchdog identities.)
- correctness_review at tests/test_watchdog.py:1: The module docstring still says 'dormant normalized event construction only', which is false after this change. The migrated test only checks isinstance after compose_pipeline(watchdog=True). It does not prove that the drain/serve production roots (__main__._locked) pass watchdog=True, so a regression in the root binding would pass. (paved road: Update the docstring. Make the positive proof go through the __main__ drain/serve composition path, or assert the root binding, rather than calling compose_pipeline with the keyword set by hand.)
