## Summary
The composition wiring and crossing rule look sound. However, reconciliation feeds the storm-breaker P0 reports back into the occurrence ledger, and the new activation test file is missing most of the proofs the acceptance criteria require.

## Findings
- correctness_review at squatch/daemon.py:254: The reconciliation loop calls record() for every Box message's reports, including messages whose origin starts with STORM_BREAKER_ORIGIN. The exclusion lives only in Box._record_occurrence, so this direct path skips it. From the second composed session onward, each P0 report is written as a storm_occurrence. The ticket requires the reserved-report exclusion to apply before reconciling Box counters so repair never feeds back into the ledger. (paved road: Skip messages whose origin starts with STORM_BREAKER_ORIGIN in the reconciliation loop, or move the origin check into the shared record() closure. Add a test that runs two sessions and asserts no storm_occurrence signature equals the report's Box signature.)
