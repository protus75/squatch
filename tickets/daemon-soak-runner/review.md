## Summary
The runner goes through the production serve graph, but it creates the evidence it then reports: it writes the Box disposition, the worker's abandoned terminal and run ids itself, and it adds the 24 injected hours by jumping the clock while no graph is running. This is the self-attested, non-member-local evidence the ticket's Definition of rejected rules out.

## Findings
- correctness_review at eval/daemon_soak.py:210: `_land_in_box` has the runner call `Box.enqueue` itself after each scenario, then returns "box" because `by_origin` finds the record the runner just wrote. So every `disposition` is self-attested and always "box". No production harvest or triage path routed the fault there. The ticket requires the disposition to be derived from the member's local run evidence, and it rejects a self-attested report. (paved road: Delete `_land_in_box`. Let the production composition (triage/harvest on the terminal or merge-conflict event) put the fault in Box or Alert. - correctness_review at eval/daemon_soak.py:181: The injected `work` stub writes its own `state_transition` events to `running` and then `abandoned`, with a hard-coded `run_seq` of 3. `_entry` then reads that stub-written `abandoned` event as the worker terminal and builds `producing_run` from it. The queue scenarios also hard-code `run_seq` 7 and 11 on the `Candidate`. So neither the terminal/event nor the 'real producing run id' comes from production. The runner fabricates both. (paved road: Let the production runner/serve path allocate the run seq and write the run's terminal when the kill lands, e.g. through the reconcile path referenced in `tests/test_restart_timers.py`. Derive `observed` and `producing_run` only from events production wrote. Do not journal state transitions from the soak harness.)

That is not 'drive the merged production serve composition ... for at least 24 injected hours'. (paved road: Advance the injected clock through the serve graph's own `sleep` seam while the graph runs, so timers, reconcile and lifecycle logic see the elapsed time.
