## Summary
The fixture host is in scope and its checks are green, but it does not match the Phase 6 fixture spec it was built for. The scripted CLI returns no canned diffs, the escape defect is pre-baked instead of introduced by a merged machine ticket, the reports lack the version-1 report schema, and zero spend depends on PATH shadowing the real `codex` binary.

## Findings
- correctness_review at hosts/fixture/bin/codex:17: The scripted agent-CLI must serve Author/Implement/Review with canned per-scenario diffs and verdicts, so the exit harness's `serve` subprocess can merge K>=3 machine tickets. The implement answer returns only {"verdict": "implemented"} and changes no files, so the implement stage produces an empty diff and no fixture ticket can reach main. All three answers are also identical for every scenario, not per scenario. (paved road: Key the canned responses by scenario (for example a ticket stem or a marker in the rendered prompt). For implement, write the scenario's canned file change into the worktree (cwd) before emitting the agent_message. Add a test that the implement call leaves a non-empty change in a temporary worktree.)
- correctness_review at hosts/fixture/app.py:8: The escape scenario must be a defect INTRODUCED by a machine-merged scenario ticket, so the escape column can attribute it through squash trailers. Here `machine-escape -> escaped` is hand-committed in the scaffold itself. Its introducing commit is therefore the scaffold commit, not a machine merge, and escape attribution cannot find a machine ticket. (paved road: Ship the base app without the escape defect. Ship the escape as the canned implement diff of a named scenario ticket, which the scripted CLI applies when serving that scenario, so the defect enters the app only through a machine merge. Update scenarios.json and the test to match.)
- correctness_review at hosts/fixture/reports/regression-report.json:1: Report fixtures must follow the normative version-1 report schema: origin `self_diagnosed|player`, summary, dedup signature, app commit/version, implicated paths (max 32), and replay `initial_state` plus action log, with an optional log excerpt. Both report files (this one and reports/escape-report.json) carry only scenario/surface/replay_file/byte counts/log_excerpt. They are missing origin, dedup signature, app version, implicated paths, and initial_state/action log, so the report-inbox consumer these fixtures exist to drive would refuse them. (paved road: Rewrite both reports with the version-1 fields. Make the replay files carry `initial_state` and an action log. Extend test_reports_are_versioned_bounded_and_describe_real_replay_files to assert the full field set as well as the byte caps.)
- correctness_review at hosts/fixture/config.yaml:4: The provider row is named `codex`, and the engine's codex adapter runs the bare `codex` binary (squatch/providers.py:201). The fixture binary is only used when a caller prepends hosts/fixture/bin to PATH, which only the test does. A `squatch serve` launched on this profile with a normal PATH runs the real billed Codex CLI, even though the profile declares est_cost_per_call_usd 0.0. The profile itself does not guarantee zero spend. (Uncertain: the plan may intend the exit harness to own the PATH, but nothing here enforces or documents that.) (paved road: Ship the zero-spend guarantee with the fixture, without editing the engine. Commit a fixture launcher entry point (for example hosts/fixture/bin/fixture-serve) that pins PATH to hosts/fixture/bin first, strips provider keys from the env, and execs serve. Add a test that `shutil.which('codex')` under that env resolves to hosts/fixture/bin/codex. If the adapter contract cannot name a binary, file that to the Suggestion Box rather than relying on ambient PATH.)
- correctness_review at tests/test_fixture_host.py:41: The test calls `sys.path.insert(0, ROOT)` and never removes it, then imports top-level modules named `replay` and `app` into sys.modules for the rest of the pytest session. Any later test or engine import of a module named `app` or `replay` gets the fixture's module, so the full-suite result depends on test order. (paved road: Use monkeypatch.syspath_prepend(ROOT) and remove the `replay` and `app` entries from sys.modules afterwards (monkeypatch.delitem), or load replay.py through importlib.util.spec_from_file_location under a unique module name.)
