## Summary
The inbox logic is mostly sound, and scope and checks are green. But publishing requires a full Journal, which makes each publisher a second journal writer; daemon consumption is never actually wired in; and exactly-once holds only by convention that the file is deleted, and nothing tests that crash point.

## Findings
- correctness_review at squatch/control.py:79: `ControlInbox.publish` runs on an instance whose constructor requires a `Journal`. `Journal.__init__` opens the active segment for append (`'ab'`) and calls `_truncate_torn_tail` on it. So any non-lock-holder process that publishes a request (for example a future CLI) must open a second append handle on the live journal. It can also truncate the tail of a segment the daemon is writing to at that moment. publish also reads the journal (`self._decided()`) to reject reused ids. This breaks the ticket's premise of 'crash-safe control intake without a second journal writer'. (paved road: Split publication from consumption. Make publish a module-level function (or a publisher class) that needs only `state_dir` and `fs` and never builds or reads a Journal. Default to uuid request ids and use an exclusive-create or temp+rename that refuses to overwrite. Leave duplicate and reused-id detection to the lock holder's `consume`, which already journals conflicts. Add a test that publishes without constructing a Journal.)
- correctness_review at squatch/daemon.py:134: Scope in says to 'hook daemon consumption under its lock-held journal'. The diff only adds a `control_consumer` factory. `DaemonTasks.__init__` still accepts only `watcher`, `merge` and `box` callbacks, and nothing composes a `ControlInbox` from the daemon's lock-held Journal. The daemon therefore never consumes the inbox. The only test runs the factory against a fake inbox. (paved road: Register the control consumer with `DaemonTasks`: add a `control` callback to its constructor and callback tuple, and update the existing `test_daemon_tasks.py` cases. Also add a composition helper that builds the `ControlInbox` from the daemon's own `Journal` and `Filesystem`. Leave `tests/test_daemon_composition.py` unchanged.)
- correctness_review at squatch/control.py:125: Exactly-once consumption depends only on the request file being deleted after `mutate`. If a crash happens after `mutate` returns but before `self._fs.unlink(path)`, or if a file with byte-identical content is written again later, the next `consume` finds a matching accepted decision and calls `mutate` a second time. For a `release`, that second call skips the hold-binding check, because `_decide` is not re-run and the hold was already discarded. The docstring pushes idempotence onto `mutate`, but the ticket requires exactly-once consumption and replay proven at crash points. The tests cover only a crash inside `mutate`. Whether at-least-once plus an idempotent `mutate` is acceptable is a judgment call; I report it because the criterion says exactly once. (paved road: After a successful mutate, journal an applied marker keyed by request id. On replay, skip `mutate` when the marker exists; if it does not, re-check the hold for release. Then add tests that crash after mutate but before unlink, and that re-deliver an identical file after consumption, and show `mutate` runs exactly once in both. If at-least-once is the intended contract, the ticket or plan must say so, and this becomes an rma.)
- correctness_review at tests/test_control.py:21: The crash-safe publication test does not exercise a crash during `publish`. It hand-writes an unrelated `.interrupted.json.tmp` file and checks that consume ignores it. It never shows that an interrupted `publish` leaves no partial `<id>.json`, and never shows what happens to a leftover temp file with the same name as a later publish. So the first acceptance criterion is only partly proven. (paved road: Inject a Filesystem whose `write` raises after writing the temp file but before the rename. Assert that no `<id>.json` exists, that `consume` makes no decision, and that re-publishing the same id then succeeds and is consumed once.)
