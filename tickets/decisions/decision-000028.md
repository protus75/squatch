No action for now. The fact is correct but costs nothing observable today. `GitError.__init__` (squatch/git.py:25) builds its message from the whole argv joined with spaces, so a failed `commit` puts the `-m` text into the exception string. The message is wrong that this only matters later: the engine log already records it. `Runner._fault` (runner.py:498-499) and the harvest path (runner.py:422-424) log `str(e)` plus a full traceback, and `harvest_error` also goes into the `state_transition` body. Still, the text that gets embedded is small and made by the engine. Almost every `Git.commit` caller passes a one-line subject: `squatch(<stem>): ticket` (tickets.py:791), `squatch(decisions): <id>` (registry.py:85), `squatch(retro): <seq>` (retro.py:311) and `squatch(<stem>): <kind>` (stages.py:1204). The only multi-line message is the squash commit (merge.py:409-410): the ticket Goal line plus two trailers, with the changed-file pathspec after it. That is a few bounded lines, not noise. It adds no secret risk either, because it holds only engine-authored ticket text and the log write seam already redacts. Shortening or quoting argv in `__str__` would change the diagnostic format every `Refusal(f"git: {e}")` caller shows, and no incident calls for that. The anti-bloat law says to wait. No rendered ticket or decision covers `GitError` formatting (decision-000021 covers `rebase` error classification, not message text), so a tombstone would be wrong. Reopen if an engine-log or refusal line from a failed commit is reported as unreadable, or if a caller starts passing unbounded or model-authored text as a commit message. Then fix `GitError` in place, for example by shortening long argv elements, and update every caller in the same change.

Evidence: squatch/git.py:19-25 (argv joined into the exception message), git.py:103-108 (commit passes -m message in argv); runner.py:422-425 and 494-506 (the engine log carries str(e) and the traceback); merge.py:407-416 (the only multi-line commit message: goal plus two trailers); tickets.py:791, registry.py:85, retro.py:311-312, stages.py:1204 (one-line subjects).
