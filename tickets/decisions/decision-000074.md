No action. The message is right that `Driver.run` puts no stage-level bound around `stage.render` (squatch/driver.py:121) or `run_gates` (driver.py:155). The per-call stuck budget covers only the model call, and it lives in `LLMEffect._call` (squatch/llmeffect.py), not in the driver. But no gate that production puts inside a Driver can hang without a bound. Implement, review, triage, diagnose, retro and requisition-review stages all build with `gates=()` (stages.py:812, :1018; triage.py:146; diagnose.py:112; retro.py:126; requisition.py:145). Verification runs outside the driver and has its own timeouts. Only two surfaces carry in-driver gates. Rework's `ReworkOrderGate` (rework.py:96-176) is a synchronous in-process check of an order. Author uses the ticket-schema gate plus `RequisitionGate` (author.py:105-108). `RequisitionGate` makes LLM calls, and each one is held to the stuck budget it inherits (requisition.py:155). It loops over a batch that `seeding.max_seeds_per_admission` limits, so its wall clock is finite. The reproduction depends on a synthetic gate that awaits forever, and no shipped gate does that. The fix the message proposes, one `asyncio.wait_for` around `Driver.run`, would bring back the primitive decision-000072 rejected. `wait_for` cancels before `abort_current` has run and hangs on a callee that resists cancellation, which breaks the abort-before-record order in llmeffect.py:11-14. A stage-level budget would also be a second timeout path beside the per-call budget, and the no-dual-path and anti-bloat laws rule that out while no incident exists. What remains is plan wording. Section 8 says 'per-stage', and the code enforces a per-call budget with gates that are either synchronous or bounded per call. This is the same point decision-000072 recorded, and its reword fix covers it. No rendered ticket covers stage-level gate time. gates-crash-continue-cancel-pin and gates-lint-before-run cover crash, cancel and lint ordering in run_gates, not a wall-clock bound, so a tombstone would be wrong. Reopen if a gate is added inside a Driver that does unbounded I/O (subprocess, network, lock wait) without its own seam timeout, or if a stage is seen running past `(retry_cap + 1) x stuck_seconds` plus a bounded gate time. Then add the bound in the same change: give that gate its own seam timeout, or make the driver's budget abort-first and cover render and gates, not `asyncio.wait_for`.

Evidence: squatch/driver.py:121 (render), :131-132 (timeout terminal from LLMEffect budget), :155 (run_gates unbounded); stage gates=() at stages.py:812, :1018, triage.py:146, diagnose.py:112, retro.py:126, requisition.py:145; in-driver gates only rework.py:176 (ReworkOrderGate, synchronous validation at :106) and author.py:105-108 (schema + RequisitionGate, whose LLM calls inherit stuck_seconds at requisition.py:155 over a seed batch limited by seeding.max_seeds_per_admission); decision-000072 on why the budget avoids wait_for (abort_current before cancel, llmeffect.py:11-14, :101-104).
