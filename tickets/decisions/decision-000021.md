No action for now. What the message says about the code is accurate, but no caller needs the distinction it asks about. `Git.rebase` (squatch/git.py:130-140) catches every `GitError`, tries `rebase --abort` and ignores any failure of that abort, then raises `RebaseConflict` with the original argv, rc, stdout and stderr. A bad `onto` ref and a real conflict therefore come out as the same exception type. The only caller is `_rebase` in squatch/merge.py:336-348. It rebases onto `"main"` right after `rev_parse(self._repo, "main")` resolves that same ref (line 339). If main were missing, that `rev_parse` would already raise a `GitError`, so a 'ref missing' failure cannot reach the rebase through this path. The caller also treats every refusal the same way: it stores the redacted stderr/stdout in `refused` and the admission re-queues. The message agrees this is adequate. The caller that does need to tell a conflict apart from other failures is the serial merge queue (squatch/mergequeue.py:229-242). It already uses a separate, merged primitive, `rebase_stop_at_conflict` (git.py:142-161). That primitive raises `RebaseConflict` only when unmerged paths exist and re-raises the plain `GitError` otherwise. So the paved road for a distinguishing caller already exists. Changing `rebase` itself would add a second classification path for a caller that does not exist, which the anti-bloat and no-dual-path laws rule out. No rendered ticket or decision covers `Git.rebase` error classification, so a tombstone would be wrong. The merged `shakeout-merge` pins the conflict-abort behaviour, not this. Reopen if a new caller of `Git.rebase` passes an `onto` that is not already resolved, or if it branches on the cause of the failure. That caller should use `rebase_stop_at_conflict` or narrow `rebase` in the same change.

Evidence: squatch/git.py:130-140 (`rebase` wraps every `GitError` as `RebaseConflict` after a best-effort abort); squatch/git.py:142-161 (`rebase_stop_at_conflict` separates conflict from other failures by checking `conflicted_paths`); squatch/merge.py:339-344 (the only `rebase` caller rev-parses main first, then treats any `RebaseConflict` as a refusal and records redacted stderr); squatch/mergequeue.py:232-242 (the merge queue uses `rebase_stop_at_conflict` and handles a non-conflict `GitError` as its own finding with REBASE_FAILURE_ROAD).
