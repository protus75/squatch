No ticket. This message describes existing, intended behavior and asks for nothing. The code matches its description. `Drain` is built with the raw parent env (squatch/__main__.py:370-372, `env=env`), not with `child_env(...)`, the call the Git seam and the CLI clients use to strip provider keys (__main__.py:346, :382, :655). `Drain._exec` (squatch/drain.py:459-462) passes that env to `self._process.run` for `UV_FORM` (`uv run python -m squatch`, drain.py:85). So the self-upgrade child, and `uv` as its launcher, both see every provider key. The plan allows this. Section 16's rule (SQUATCH_PLAN.md:1082, :1394) withholds a key only from a process that does not need it, such as verification commands, checks, and evidence replay. The handoff child is squatch itself, and its Stages, Box, and Diagnose calls need every configured provider's key so they can re-inject each one per call. D1 names `uv` as the one runtime exception (drain.py:46-48). A `uv` subprocess that sees the env is the cost of that exception. Stripping keys from the handoff would break the child's provider calls, and adding a separate key channel for the child alongside the env would be a second path, which the no-dual-path rule rules out. A tombstone does not fit. decision-000208 covers the handoff child's stdin, decisions 000203/000204 cover the deadline and merge tally the handoff carries, and none of them covers its environment. No rendered open ticket or merged Goal line does either. The message has no evidence (evidence: None) and comes from `bootstrap-ingest`, so under D10 any change would be speculative.

Evidence: squatch/__main__.py:370-372 builds Drain with the raw `env`. :346, :382 and :655 build Git with `child_env(env, {p.auth ...})`. squatch/drain.py:85 defines UV_FORM, and :459-462 runs `_exec` with `env=self._env`. drain.py:46-48 is the docstring naming D1's one runtime `uv` exception. SQUATCH_PLAN.md:1082 states the inherit-minus-secrets child env, under which a key is withheld only from children that do not need it, and :1394 gives the section 16 rule. Reopen if the handoff child stops making provider calls itself (for example, if provider calls move into a separate key-holding process), if the plan narrows D1's `uv` exception or requires keys to be passed to the handoff by a channel other than the env, or if a key is traced as leaking through `uv`'s own logging, caching, or subprocesses.
