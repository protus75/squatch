No ticket for now. The code fact in the message is correct, but the failure looks unreachable on the live path, and the fix it asks for is a choice in the plan, which only the operator can make. Verified: `LLMEffect.call` rebuilds a replay with `LLMResult(**recorded)` (squatch/llmeffect.py:52). `LLMResult` is a frozen dataclass (squatch/llm.py:52-53), so a recorded body with an unknown field, or one missing a field that has no default, raises TypeError. The journal envelope's `v` is versioned per event `type` (SQUATCH_PLAN.md:981), not per effect result, so an `effect_completion` body carries no result version. Why it does not bite today: replay only comes from a completed key under the same run sequence. The llmeffect.py docstring (:6-9) says a fresh run sequence takes fresh keys. Changing the `LLMResult` field set means a new engine release, which means a restart, and on restart reconcile reaps the in-flight run as `abandoned` and the stem comes back under a fresh run sequence (merged shakeout-reconcile). So a completion recorded by an older release is never replayed under its old key. I have not checked every replay path, such as ticket-less surfaces like triage and author, whose keys use message.seq and pass_number (decision-000113). If one of them can replay across a restart without a fresh counter, the TypeError becomes reachable and should be authored as a bug. Either fix the message offers changes section 6 prose: (a) a completion that fails to rebuild is treated as intent-only and re-run fresh, or (b) a `v` on the recorded result. A code ticket written now would have to guess which one the operator picks. Engine tickets cannot write plan prose, which is why decisions -000105, -000113, -000115 and -000116 also went to the operator. Nothing rendered covers this: effects-completion-result-corruption covers a missing `result` field (a KeyError in `Effects(...)`), not a result-shape mismatch at rebuild, and decision-000113 covers the shape of the key, not the result. A tombstone would therefore be wrong.

Evidence: squatch/llmeffect.py:52 `return LLMResult(**await self._call(...))`. squatch/llm.py:52-53 `@dataclass(frozen=True) class LLMResult`. SQUATCH_PLAN.md:981 envelope `v` = event-schema version per `type`. squatch/llmeffect.py:6-9 docstring: completed key replays; a fresh run sequence takes fresh keys. Optional operator action: in section 6, state that the effect result's schema is pinned by the event `v` of `effect_completion` (bump `v` when `LLMResult` changes, and the reader refuses or treats an older-`v` completion as intent-only), or state that cross-release replay cannot happen because reconcile always issues a fresh run sequence. Reopen if a replay path is found that survives a restart under the same key (especially on the triage, author or retro surfaces), if `LLMResult` gains or loses a field while a run is in flight, or if the operator settles the section 6 wording.
