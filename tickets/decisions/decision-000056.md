No ticket for now. The message is right about the code: `run_gates` in squatch/gates.py (lines 186-190) turns any non-`GateError` exception into a hard finding whose message includes `{type(e).__name__}: {e}`, and it has no redactor of its own. Half of the stated risk is already handled. Every engine-log line goes through the redaction seam (`EngineLog._scrub`, squatch/enginelog.py:35-61), so the check event that logs `invoice.hard_findings` (squatch/stages.py:950-952) is scrubbed. The part not covered is the check effect's completion body and the `checks.json` lift. The squatch/redact.py writer checklist only says those carry post-scrub text for Verification, which redacts its own output (stages.py:379, 406, 434). The specific scenario in the message, a gate running a tool with a key in argv, can't happen under the current design. Every gate that runs a subprocess (Verification, BugEvidence, the merge safety tier) gets `_child_env`, which is built by `child_env` (squatch/providers.py:378-381, stages.py:638, merge.py:188). That function removes every configured `auth` env var, so a gate child never has a provider key to echo. Only `CliClient` adds a key back, and it is not a gate. The message cites no incident, no crash, and no leaked value (`evidence: None`), and D10 says every addition must cite the incident that earned it. A redactor parameter on `run_gates` and a new writer-checklist entry would be speculative hardening. A tombstone doesn't fit: open_work gates-crash-continue-cancel-pin tests crash continuation and cancellation, not redaction of crash text, and no rendered decision covers this.

Evidence: squatch/gates.py:186-190 builds the crash message from str(e) with no redaction. squatch/enginelog.py:35-61 redacts every engine-log record, including the check event at squatch/stages.py:950-952. squatch/providers.py:378-381 child_env removes all configured auth env vars, and gate subprocesses use it (stages.py:638, merge.py:188). The squatch/redact.py writer checklist names Verification, not run_gates, as the scrubber for checks.json and check-completion text. The message carries evidence: None. Reopen if any gate's crash text in a journal check completion or a lifted checks.json is found to contain a configured secret value; if a gate is ever given an env or argv that holds a provider key; if a gate that reads secret-bearing files or config lands; or if the redact.py writer checklist is revised to treat exception text as a captured stream.
