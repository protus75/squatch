No ticket. The code fact is right, but the request is out of date: the seeding deliverable has already merged, and it does not use the loose default resolver the message describes. `Intake.commit` falls back to `_resolver(exclude={stem})` (squatch/tickets.py:770), which accepts any `tickets/<s>/ticket.md` on disk, committed or not. `Intake.run` (squatch/tickets.py:718-752) excludes pending stems that are not yet done and commits in topological order. The machine seed lift does not rely on the fallback. `_lift_seeds` (squatch/stages.py:1058-1114, merged in requisition-review-seed and covered end to end by seed-successor-proof) passes its own `resolve`, which is batch membership or an existing ticket dir. It also lints every seed and checks the reviewed blob identity before the first ticket-plane commit (:1069-1077), and its replay map makes a partly committed batch resumable inside the one effect. A seed can depend on a sibling in its reviewed batch, which section 13's 'or one intaken in the same batch' wording (operator action in decision-000122) already allows, so per-seed `depends` ordering under `run`'s strictness would add nothing. The two other machine `commit` callers lint against existing dirs: author.py:196-200 lints before `intake.commit` at :226, and runner.py:223 re-stamps an existing draft at confirm. The one remaining gap is theoretical. In the main checkout, an existing-dir resolver (seed lift, author lint, or the default) can accept an untracked human-authored ticket that `Intake.run` has not intaken yet. If intake later refuses it, the dependent holds a `Depends on` that never merges. No incident has shown this. Authoring a fix now would be speculative, against the build-the-simplest-thing rule, and how strict grammar-time resolution should be is plan wording the operator owns (decision-000122). No rendered work or decision covers the uncommitted-neighbour case. decision-000122 covers which sources resolve a stem, not whether those dirs are committed, so a tombstone would be wrong. Reopen if a machine-authored or seeded ticket is committed with a `Depends on` stem that has no ticket-plane commit, if a dependent is stranded behind an intake-refused human ticket, or if a regeneration of section 13 or the seed path changes the batch resolver.
