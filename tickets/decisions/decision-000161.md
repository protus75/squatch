No ticket. The message is mostly right but gets one detail wrong. `_restore_ticket_plane` (squatch/merge.py:350-362) builds its unlink list with `_entries_below` (:70-76). That helper calls raw `Path.is_symlink`, `Path.is_dir` and `Path.iterdir` directly, and only the deletion itself goes through the `fs.unlink` seam. It does not use `rglob`, as the message says. The plain recursion is deliberate: it never follows a symlink, so a link an agent plants out of the worktree can never get its target deleted. Any replacement has to keep that property. The `Filesystem` protocol (squatch/seams.py:38-65) has no symlink-safe recursive walk. Its `list` only does pattern matching inside one directory, so 'move enumeration behind the seam' would mean adding a new seam method. The alternative, a `git ls-files --others` read, would also need to keep the no-follow guarantee. merge.py is not the only place that reads directories raw. Engine code does it in many modules: stages.py:857-859 and :1166-1167 (`rglob` in the lift), harvest.py:72-81 (`rglob` plus `is_symlink`), tickets.py:804-806, status.py:178-180, author.py:277, diagnose.py:137, runner.py:404, box.py:217, registry.py:60, journal.py:176 and audit.py:196-209. Today the seam rule is applied to mutations (write, unlink, replace, remove) and not to directory enumeration. Moving only merge.py behind the seam would leave two enumeration styles in the engine, which the no-dual-path rule forbids. Moving every site would be a wide refactor that no incident has earned. The message cites no evidence, the merge tests already exercise this path on real temporary worktrees, and Phases 2-6 merged through it. Under the build-the-simplest-thing rule (D10), that makes the change speculative. decision-000155 and decision-000156 declined other cross-cutting refactors for the same reason. No rendered work or decision covers whether directory enumeration goes through the Filesystem seam. decision-000153 covers only the wording of the restore step, so a tombstone would be wrong. Optional operator action: if section 15 is meant to cover read-side directory enumeration, say so in the plan and add a symlink-safe walk to the Filesystem seam. Then regenerate every enumeration site together.
