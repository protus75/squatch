No ticket. The two record shapes the message describes are real, but the conflict it predicts does not happen. Both seeds have merged. spine-harvest records a harvest failure as a `harvest_error` string (`"<ExcType>: <msg>"`) in the body of the run's terminal `state_transition` (squatch/runner.py:403-433, :460-461). Reconcile does the same for an orphan (squatch/reconcile.py:95-101), and each also writes a `harvest_error` line to the engine log. So the failure is journaled, which is what section 11.2 requires: 'a harvest error journals a finding and dispatch proceeds'. Section 6 (SQUATCH_PLAN.md:1015) also lists 'a harvest error' among the load-bearing failures that are 'ALSO journaled as events'. Neither passage names a closed `Finding` record or a separate event type. Their lowercase 'finding' is satisfied by the journaled terminal field, and tests/test_terminal.py:776 and :798 pin it. The reader the message worries about, spine-diagnosis (batch 2), reads neither shape. `squatch/diagnose.py:160-168` reads only the on-disk `attempts/<n>/harvest.json` and renders `(harvest unavailable)` when the file is missing. A harvest error therefore reaches diagnosis the same way whichever shape was journaled. Changing to a typed `Finding` would rewrite the plan and regenerate two merged seeds without fixing any failure. Under D10 that is speculative: the message gives no evidence and comes from `bootstrap-ingest`. A tombstone does not fit. spine-harvest and spine-diagnosis own the code involved, but neither rendered Goal covers how the harvest-error record is shaped. Reopen if a consumer (diagnosis, status, audit, or a retro) needs to read harvest failures from the journal in a typed form, if a regeneration of spine-harvest drops `harvest_error` from the terminal body, or if plan section 11.2 or 6 is edited for another reason. In that last case the wording could name the `harvest_error` terminal field exactly in the same change.

Evidence: squatch/runner.py:403-461 (harvest_error carried in terminal state_transition body); squatch/reconcile.py:95-101 (same shape for orphans); squatch/diagnose.py:160-168 (diagnosis reads harvest.json only, renders '(harvest unavailable)'); tests/test_terminal.py:776,798 (terminal body pin); SQUATCH_PLAN.md:1015 and section 11.2 harvest-soft sentence (lowercase 'finding', no closed record named); message evidence: None, origin bootstrap-ingest.
