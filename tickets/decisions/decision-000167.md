No ticket. The facts in the message are right, and the message itself calls the behavior harmless. In fact there are more instances than it counts: `EngineLog` is built at squatch/__main__.py:545 and :705, squatch/stages.py:1226, squatch/merge.py:567, and squatch/serve.py:224 and :236. Building it in several places does no harm because of how `EngineLog` (squatch/enginelog.py:23-46) works. Its only state is the path, the clock and the redactor. It does not keep a file handle open. `event` opens `<state_dir>/engine.log` in append mode, writes one whole line and closes it, every time. It also reads the size from the file before every write to decide whether to rotate. It is synchronous, so in one event-loop process two instances cannot interleave a write or a rotation. Every instance gets the same redactor, so redaction does not depend on which instance writes. The log is diagnostic only (section 6): no gate or dispatch decision reads it. So the extra instances cannot cause divergence, a lost line or unredacted output. The fix the message proposes depends on a 'single composition root' for merge/stages. That refactor was declined earlier as speculative under D10 (decision-000156 cites decision-000155 as the precedent). Passing the log down from the runner only makes sense as part of that root. Doing it alone at one site would leave mixed construction styles, which the no-dual-path rule forbids. The message cites no evidence, and Phases 2-6 merged on the current layout. A tombstone would be wrong because no rendered work or decision covers how EngineLog instances are shared. decision-000155 is not in the rendered projection, and none of the open tickets touch engine-log construction.

Evidence: squatch/enginelog.py:23-46 (stateless apart from path/clock/redact; open-append-close for each event; size is checked before every write, and rotation moves whole files); EngineLog construction sites: __main__.py:545, :705; stages.py:1226; merge.py:567; serve.py:224, :236. The message's evidence is None. Reopen if the engine log shows a split or interleaved line, a lost line around a rotation, or a line redacted differently depending on which instance wrote it; if EngineLog gains per-instance state such as a held file handle, buffering or an in-memory size counter; if engines start running as more than one process against one state_dir; or if the operator approves the single composition root refactor, in which case the log should be passed down as part of that change.
