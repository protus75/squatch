No ticket: this is a plan-text problem, and the operator has to fix it in the plan. The message is right. SQUATCH_PLAN.md:304 tells prompt 1 to write the literal `OPERATOR-SETS-THIS` into every operator-owned value, naming model ids, `auth` env-var names and `est_cost_per_call_usd`, and it calls the result 'schema-valid'. For two of those three slots that is false. `Provider.auth` goes through `_auth_is_an_env_var_name` (squatch/config.py:68-74), which only accepts `[A-Z_][A-Z0-9_]*`, so a value with hyphens fails to load. `Limits.est_cost_per_call_usd` is `float | None` with `ge=0` (config.py:57), so a string fails too. The code is behaving correctly here: the auth check deliberately allows only names, never a literal secret, and the float type is what makes cost accounting work. The plan is the thing that is wrong. That makes it a seed defect, and the plan-is-the-seed rule puts the fix in plan prose. Engine tickets cannot write plan prose, which is why decisions -000072, -000074, -000079, -000080, -000091 and -000092 were also sent to the operator. There is one code consequence. `PLACEHOLDER in (model, provider.auth)` at squatch/providers.py:411 and squatch/baseline.py:83 can never be true for `auth` on a config that loaded. The only thing that reaches it is tests/test_baseline.py:101, which sets the field after load and so skips the validator. Once the plan is reworded, a regeneration should decide whether to keep that check. Leaving it now is harmless, and the no-dual-path rule says to change it together with the plan. Nothing in the rendered work or decisions covers which value types the placeholder may go in. config-numeric-bool-strict is about YAML bools in numeric fields. host-contract-null-rule is about explicit nulls, and an omitted `auth`/`est_cost_per_call_usd` is the documented way to leave a value unset. The other open config-* tickets have different scopes. So a tombstone would be wrong. The live-run stop the message reports is the intended fail-closed refusal, not a bug, and it is cleared by the operator setting the model ids. Operator action: (1) reword SQUATCH_PLAN.md:304 so the placeholder applies only to string-typed operator values (model ids). Optional slots that are not plain strings are left out instead: `auth` is omitted when the CLI uses ambient login, and `est_cost_per_call_usd` is omitted or set to the plan's recommended number. (2) In the same edit, decide whether the `provider.auth` placeholder check at providers.py:411 and baseline.py:83, plus the injection in its test, should be dropped as unreachable, and regenerate those deliverables together. (3) Set the real model ids in config.yaml so prompt 2 can make a live run. Reopen if: a regeneration writes the placeholder into `auth` or a numeric field and the config fails to load; the auth validator is loosened so it accepts the placeholder; or the operator has not fixed the plan by the reopen date.
