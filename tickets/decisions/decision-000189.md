No ticket. The behavior is real, but the plan allows it and it does not change the outcome. `Drain._reoffers` (squatch/drain.py:369-377) sorts the re-offerable parked stems with the same `sort_key` used for dispatch, which is (priority, has-no-intake, first-intake ts, stem). `_select_offer` takes `offers[0]`. Because `cap_consumed` draws are not part of the key, the stem that sorts first keeps being re-offered until its `retry` cap is spent, it is routed to the Reject queue, or it merges. Only then does the next parked stem get a turn. Section 18 (SQUATCH_PLAN.md:563-570) only requires that each parked stem with `retry` budget is re-offered, one unit per re-offer, with eligible work first and quiescence re-checked after each re-offer merge. It sets no order among re-offers, and the module docstring (drain.py:16-17) says "in the same order". Within one invocation every parked stem still gets its full lifetime budget, so the total draws, the terminals reached and the Reject-queue routing are the same under either order. Only the interleaving changes. The Phase 2 spine the message defers to has already shipped on this order without changing it: spine-caps, spine-diagnosis, shakeout-ladder and shakeout-drain are all merged, and shakeout-drain pins the one-retry-draw re-offer path. Adding a draws-so-far leading key would mean a plan edit plus new drain fold state, with no observed failure behind it (evidence: None). Under D10 that is speculative. A tombstone does not fit: no rendered open ticket, merged Goal line or decision covers fairness in re-offer order. drain-parked-detail only changes the `parked:` report line. Reopen if a `drain.max_runtime_hours` ceiling halt (or a kill) is journaled while some parked stem with remaining `retry` budget was never re-offered and another stem drew several units in that invocation, if the plan adds an ordering rule for re-offers, or if serve's scheduler takes on re-offers and needs a fairness rule.

Evidence: squatch/drain.py:145-149 (sort_key has no draw count), :236-240 (re-offers only run when the eligible queue is empty; first offer selected), :369-377 (_reoffers sorts by sort_key); SQUATCH_PLAN.md:563-570 (section 18 re-offer contract sets no order among re-offers); merged spine-caps, spine-diagnosis, shakeout-ladder, shakeout-drain kept this ordering; message evidence: None (a synthetic probe, no observed incident).
