No ticket. The facts in the message are right. `Runner._fault` (squatch/runner.py:494-506) builds the operator `Refusal` from `str(e)`, and for `ExecutableNotFound` from the binary name too. `main` prints it as `refused:` / `paved road:` (squatch/__main__.py:128-130), and `report` lines go straight to `print` (__main__.py:344, :387, :546, :713), so none of them pass through the Redactor. The engine-log line at runner.py:498 does pass through it. But the plan does not count operator stdout as a captured stream. Section 6 (SQUATCH_PLAN.md:1017) lists the streams that must be redacted as journal bodies, engine log, spools and harvested artifacts. Its closed WRITER-SITE checklist names the journal writer, the engine-log writer, the attempt-spool writer and harvest serialization. Stdout is not on that list, and squatch never persists stdout itself. Section 16 (:1363) says the same: the seam scrubs streams 'before it persists'. So the current code matches the plan, and redacting operator output would add a new captured stream to section 6. The plan is the seed, so the plan has to change first, and that is the operator's call. The leak is also unlikely in practice. Configured secrets are the provider `auth` env values, and they are injected only into the one provider call that needs them (section 6). An `ExecutableNotFound` names a binary, and a generic fault message is a Python exception string from engine code. Neither path normally carries a secret value. The full exception, with its traceback, goes to the redacted engine log. The message cites no evidence, and Phases 3-6 (including serve-activation and soak-run) merged on this output path. Under D10 the change is speculative. A tombstone would be wrong because no rendered work or decision covers redacting operator stdout. decision-000166 covers only whether a missing binary should refuse or park, not how the refusal text is scrubbed. Optional operator action: if a daemon's captured stdout or stderr should count as a persisted stream, add the operator-print seam (the `report` callable and the `refused:` print in `main`) to the section 6 writer-site checklist. Then regenerate __main__.py and runner.py so that one Redactor built from config is wired into that seam, with a config-to-print regression test. Reopen if the operator changes section 6 that way, or if any stdout/stderr capture, operator transcript or daemon log is found to contain a configured secret value.
