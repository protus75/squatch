No ticket. The message's one forward-looking requirement is already built. Seeds authored after the Phase 2 exit go through the seed lift that merged under requisition-review-seed and phase2-exit, which lifts each approved seed 'with their authoring-commit signals'. The code agrees: each lifted seed journals a `ticket_intake` signal with `source: seed` and its `seeder` (squatch/seeds.py:153-157). So every self-hosted seeding path now emits the event that section 9 requires. What is left is a fixed, historical set: the conductor's prompt 14-17 seeds, committed in the bootstrap commit with no intake signal. Two effects are real but small. (1) `Drain._fold` (squatch/drain.py:134-135) sets `first` only from intake signals, so those stems had no age term and sorted last. The message itself says this was harmless, because `priority` and `depends` fixed the Phase 2 order, and Phase 2 through Phase 6 have since merged. (2) `status.project` (squatch/status.py:93-103) skips only intaken stems when it builds `pending`, so a lint-clean conductor seed still on disk would show under 'pending intake' even after it merged. That is a cosmetic misreport in a derived projection (D3). It does not affect dispatch, because `Drain._scan` excludes merged stems (drain.py:306). Fixing it would take either a one-time backfill of intake events into a versioned journal or a status special case for pre-intake stems. The backfill would write synthetic history into the record. The special case would be a second classification path for a set that can never grow. Neither has an incident behind it: the message gives no evidence and comes from `bootstrap-ingest`, so under D10 either change would be speculative. A tombstone does not fit. requisition-review-seed covers the seed path's intake signal, but no rendered ticket or decision covers the conductor seeds' missing signal or how status shows them.

Evidence: squatch/seeds.py:153-157 (the seed lift journals `ticket_intake` with source=seed); merged requisition-review-seed and phase2-exit Goal lines ('with their authoring-commit signals'); squatch/drain.py:134-135 (`first` comes only from intake signals) and :306 (merged stems are never scanned); squatch/status.py:93-103 (`pending` skips only intaken stems, not merged ones). Not verified: whether the live journal actually has no intake signal for every conductor seed. Reopen if `squatch status` misleads an operator by listing merged conductor seeds under 'pending intake', if any sanctioned authoring path is found committing a ticket without a `ticket_intake` signal, or if status.py's pending fold is restructured for another reason, since excluding merged stems could then be done in the same change.
