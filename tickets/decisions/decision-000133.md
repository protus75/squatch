No ticket. The code fact is correct. `project` in squatch/status.py:88-103 skips every on-disk stem that already has an intake signal (:94). It lints only the stems that have none, and puts each one in `unparsed` or `pending`. Status reads only the journal and the disk and never compares a committed ticket.md against its intaken commit. So an edited, already-intaken ticket still shows under its earlier intake record until a later intake pass journals a new signal. The message itself says this is acceptable and needs no work. The surface it defers to has already merged. scheduler-activation and serve-activation built the Phase 3 watcher, and under serve the production `priority_snapshot` runs `Intake.run` on every cycle (squatch/serve.py, as decision-000127 records). Re-intake therefore happens on the watcher's cadence and does not wait for a manual `run`/`drain`. The plan makes status a read-only projection (status-projection, merged), and comparing against git to spot modified committed tickets would add a git read to a surface that deliberately has none. No incident shows an operator misled by this gap, so adding it now would be a speculative feature. No rendered work or decision covers how status sees modified committed tickets. status-projection built the projection without discussing this case, and decision-000127 covers intake cost, not status visibility, so a tombstone would be wrong. Reopen if an operator acts on a stale status view of an edited ticket, if a recovery edit sits un-reintaken across watcher cycles under serve, or if a regeneration of status or intake changes how intake signals are matched to the committed ticket bytes.

Evidence: squatch/status.py:61-103 (intake-signal fold at :72-74; on-disk stems with a signal are skipped at :94; only unsignalled stems are linted into unparsed/pending at :96-103). These merged tickets show the watcher surface the message defers to is live: scheduler-activation, serve-activation, status-projection. decision-000127 records that serve.py's priority_snapshot runs Intake.run on every cycle.
