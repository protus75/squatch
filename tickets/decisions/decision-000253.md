No ticket. The hand list in tests/test_seeded_phase2.py is deliberate. Its comment (lines 97-100) calls `CONTEXT_REFUSED` historical pinned material, like the `EXISTING_AT_AUTHORING` byte counts, so that later edits cannot change whether an already-admitted seed was renderable. `test_context_refused_set_matches_phase2_authoring_snapshot` (line 217) pins that snapshot exactly. If the set were derived from `DATA_MARKER` over `EXISTING_AT_AUTHORING`, the result would depend on the live file contents, because the dict holds only paths and sizes. That is the live-listing drift the fixture exists to prevent: a later marker-carrying edit to a named file would turn a finished Phase 2 seed red. The defect class this message is concerned with is already caught where it happens. Every merged Phase 2 seed is in merged_work and Phase 2 is closed. Later seed tests check `DATA_MARKER` against live Context files at authoring time (tests/test_seeded_phase4_core.py:135, tests/test_seeded_phase5_01.py:111). Requisition review also measures each authored or seeded ticket's render before it commits (requisition-review-call/author/seed merged), and `Spec.render` refuses a block carrying the delimiter (squatch/specs.py:128). So a new marker-carrying Context file is refused at authoring, not discovered at dispatch. Changing a finished phase's pinned fixture would mean regenerating merged work with no failure behind it. The message gives no evidence and comes from bootstrap-ingest, so under D10 the change would be speculative. No rendered Goal or decision covers this fixture's derivation, so a tombstone does not fit.

Evidence: tests/test_seeded_phase2.py:97-110 (CONTEXT_REFUSED documented as historical pinned material) and :217-222 (snapshot pin); tests/test_seeded_phase4_core.py:135 and tests/test_seeded_phase5_01.py:111 (live DATA_MARKER checks on later seeds' Context); squatch/specs.py:128 (render refuses delimiter-carrying blocks); requisition-review-* and phase2-exit in merged_work. Reopen if a seed or authored ticket that passed requisition review is parked at dispatch for a delimiter-carrying Context file, or if any Phase 2 seed is regenerated.
