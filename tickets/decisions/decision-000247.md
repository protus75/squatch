No ticket. What the message says about the code is correct, and the hazard it implies does not exist. `orphans` in squatch/reconcile.py:50-52 skips every event whose `ticket` is None. Triage drives its stage with `ticket=None` (squatch/triage.py:224), so if a crash leaves a triage `effect_intent` open, reconcile never reaps or reports it. That is harmless because effects.py treats a key that has an intent but no completion as one to re-execute (squatch/effects.py:10, :56-58). The message's reason, that the next pass keys a fresh `<pass>`, is not always true. `pass_number` counts the `triage_pass` signals (triage.py:190-192), and that signal is only appended after the pass loop finishes (:249). So a pass that crashes mid-loop can run again under the same pass number and the same `llm/...` keys. Even then nothing collides and nothing is double-charged in a way that matters. The open intent is re-run as designed, and a message without a recorded verdict stays `pending` for the next pass. The ticket is box-triage, which has already run: its checks.json, review.md and run.md are on disk. It does not appear in the rendered merged_work or open_work projections, so a tombstone link is not valid. Rewording a finished ticket's Scope out would add change history with no failure behind it. The message gives no evidence and comes from bootstrap-ingest, so under D10 that edit would be speculative.
