No ticket. The message is right about the mismatch, but the fix is either an edit to plan prose, which only the operator can make, or a code change that would break things that work today. SQUATCH_PLAN.md:1427 (section 18, Invocation) says the project stays a VIRTUAL uv project (`package = false`, no build backend) until the release path. Line 447 also says 'virtual (no console script until the release path ...)'. pyproject.toml contradicts this. It declares `[build-system]` with `uv_build` and sets `[tool.uv.build-backend] module-root = ""` for the flat layout, so the venv installs squatch editable. It declares no `[project.scripts]`, so the half of the rule that matters is met: there is no console script and bare `squatch` is never assumed on `$PATH`. Nothing is broken today. `uv run python -m squatch` works from any cwd only because squatch is installed in the venv. A code ticket that removed the build backend to match the plan would make the module entry depend on cwd, which is a regression with no gain. That leaves the plan wording as the thing to fix. Engine tickets cannot write plan prose, so a code ticket would have nothing it is allowed to edit. Decisions -000105, -000113, -000115, -000116, -000119, -000120 and -000122 went to the operator for the same reason. No release-path deliverable (section 13 touchpoint 6) appears in open or merged work, so there is nothing to defer this onto either. No rendered work or decision covers packaging or the build backend. startup-interpreter-floor touches `squatch.__main__` but only the Python version floor, so a tombstone would be wrong. Operator action: at SQUATCH_PLAN.md:1427, and in the matching clause at :447, replace 'VIRTUAL uv project (`package = false`, no build backend)' with 'an editable-installed uv project with no `[project.scripts]` console script', and keep the rest of the clause about the release path putting bare `squatch` on `$PATH`. Then regenerate and confirm that pyproject.toml is unchanged. Reopen if the operator has not settled the wording by the reopen date, if a regeneration removes `[build-system]` or adds a console script, or if a release-path deliverable is authored.

Evidence: SQUATCH_PLAN.md:1427 and :447 call for a virtual project with no build backend. pyproject.toml has `[build-system] requires = ["uv_build>=0.11,<0.12"]`, `build-backend = "uv_build"` and `[tool.uv.build-backend] module-root = ""`, and no `[project.scripts]`. Nothing in open_work or merged_work covers the release path or packaging.
