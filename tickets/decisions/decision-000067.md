No action. The message is right about the code, and it asks for a plan-level choice, not a fix to a defect. Two engine modules append without the filesystem seam: `EngineLog.event` opens `engine.log` with `open("ab")` and `_rotate` calls `os.replace` directly (squatch/enginelog.py:39, :46), and `Journal` keeps its active segment open with `open("ab")` (squatch/journal.py:97). The `Filesystem` Protocol has only atomic whole-file `write` (temp file, fsync, rename) and `replace` (squatch/seams.py:38-43). An append-only log cannot use that shape without rewriting the whole file on every line. The seams.py docstring says each seam 'grows only with a consumer', so neither module could have used the seam as it stands. Nothing is broken. No test or gate needs a fake append: both modules are tested against real temporary state dirs. The engine log is non-authoritative, and the journal's corruption-strict reader is the integrity check for its bytes. No incident has come from these raw writes. An append seam would mean changing the journal's durable write path, which is the most corruption-sensitive writer in the engine, with nothing to show for it. The anti-bloat law does not allow that. The mismatch is in the wording. seams.py:3 and the section 15 seams rule say that engine code never writes a file raw, and neither names append-only logs as exempt. The message says the lockfile is exempt, but neither the plan nor seams.py records that either. This matches how decision-000053, decision-000062 and decision-000064 handled small plan/code wording gaps: the merged code is consistent, nothing is blocked, and a plan regeneration would not produce wrong code, because the seam's documented shape cannot express an append. No rendered ticket or decision covers append-shaped filesystem writes. The open journal-segment-utc-date and journal-event-type-corruption tickets are about segment naming and parse strictness, not the write seam, so a tombstone would be wrong. Reopen if a test or gate needs to fake or observe appended log bytes, or if a third raw appender appears. At that point, grow one `append` shape on `Filesystem` and move journal.py and enginelog.py onto it in the same change. Also reopen if the operator treats the missing wording as a plan defect. The fix then is one clause in section 15, naming the journal, the engine log and the lockfile as the raw-write exemptions and giving the reason.

Evidence: squatch/enginelog.py:39 `self.path.open("ab")`; squatch/enginelog.py:46 `os.replace(...)`; squatch/journal.py:97 `self._active.open("ab")`; squatch/seams.py:3-5 (never writes a file raw; seam grows only with a consumer) and :38-43 (Filesystem has write/replace only); SQUATCH_PLAN.md:1393 seams rule with no append/log exemption; grep finds no append or lockfile exemption in the plan's seam text or in seams.py; no open ticket or decision covers this.
