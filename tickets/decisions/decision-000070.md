No action. The message describes the code correctly and says itself that nothing breaks. `FakeLLM` in squatch/llm.py:88 sets `kind = "cli"` to satisfy the `LLM` Protocol attribute `kind: Literal["api", "cli"]` (llm.py:63). The only kind the section 6 vocabulary could give it is one of the two real styles. No engine code reads `kind` from an LLM instance. A search for `client.kind`, `llm.kind` and `fake*.kind` across the repo finds nothing. Every `kind` branch involving providers reads the configured provider's `kind` from config (squatch/providers.py:265, :294, :330; squatch/config.py:79; squatch/thresh.py:67), not the client object that makes the call. So the value on the fake cannot change routing, write grants, stdin delivery or threshold behaviour, and a test using `FakeLLM` does not follow a cli-only path because of it. Adding a third value such as `"fake"` to the Protocol literal would put a test-only member into a closed section 6 vocabulary that production adapters must match. Making the attribute optional would weaken the Protocol for every real adapter. The anti-bloat and closed-vocabulary laws rule out both, and no incident has earned either. No rendered ticket or decision covers the LLM Protocol's `kind` attribute. The open config-*, gates-*, journal-*, lockfile-*, seams-* and effects-* tickets are unrelated, so a tombstone would be wrong. Reopen when engine code first branches on an LLM instance's `kind` rather than the configured provider's. That change must then choose in the same diff: either the fake takes the kind of the provider it stands in for, as a constructor argument, or the branch moves to the config provider kind that every current consumer already reads.

Evidence: squatch/llm.py:63 (Protocol `kind: Literal["api", "cli"]`), llm.py:88 (`FakeLLM.kind = "cli"`); squatch/watchdog.py:139 (`WatchdogLLM.kind = "cli"`), squatch/providers.py:387 (`CliClient.kind = "cli"`); every `kind` branch involving providers reads the config provider: providers.py:265, :294, :330, config.py:79, thresh.py:67; a repo-wide grep for `(client|llm|_llm|fake)\w*\.kind` returns no matches.
