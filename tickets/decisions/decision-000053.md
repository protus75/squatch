No action. The message asks for two things: the first closed-vocab gate should add the one "value outside allowed set" helper it needs, and there should be no helper library. The merged code already does both. The `ticket_schema` gate in squatch/tickets.py (CODE = "ticket_schema", line 36) has a local `vocab(key, allowed)` helper at lines 178-181. When a frontmatter value is not a string in the allowed set, the helper adds a `ticket_schema` finding ("<key> <value> is not one of [...]") that carries a paved road. Line 171 applies the same allowlist rule to unknown frontmatter keys. squatch/gates.py has no `allowed:` helpers, and `Gate` is a `Protocol` (gates.py:105), not a base class with helpers. So no speculative helper library exists, which is what the anti-bloat law wants. Adding one now, or moving `vocab` into gates.py with no second consumer, would be churn that no incident has earned. Section 7 rung 2 (SQUATCH_PLAN.md:1101) still says the Gate base class offers `allowed:`-style helpers. The part of that rule that has force is "allowlists, never denylists", and the code follows it. The wording about where the helper lives is a small mismatch between plan and code, and it blocks nothing. No rendered ticket or decision covers gate allowlist helpers. The open `config-gate-code-vocab` checks config keys against GATE_CODES, not gate helpers, so a tombstone against it would be wrong. Reopen if a second gate needs the same out-of-allowed-set check. In that case, move `vocab` into gates.py and update tickets.py in the same change. Or, if the rung 2 wording is judged a plan defect, fix the plan to say allowlist checks live with the gate that owns the vocabulary.

Evidence: squatch/tickets.py:36 CODE = "ticket_schema"; squatch/tickets.py:178-181 `def vocab(key, allowed)` appends a finding `f"{key} {v!r} is not one of {sorted(allowed)}"`; squatch/tickets.py:171 closed-schema key allowlist finding; squatch/gates.py:105 `class Gate(Protocol)`, with no allowed-helper functions in the module; SQUATCH_PLAN.md:1101 rung 2 wording.
