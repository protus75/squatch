The message describes the fixture correctly, but changing it would be a test-only refactor with no failure behind it. tests/test_drain_reentry.py writes its widget to `squatch/widget.py` (lines 51, 54, 163, 226). Each admission is therefore a self-upgrade, and the harness swaps the `uv` handoff spawn for `NoHandoff` (lines 83-94), which returns 0 and sends every other argv through the real `SubprocessExec`. The coupling is deliberate and documented in a comment at lines 122-123. The test also relies on it: line 228 asserts `self-upgrade: widget-module touched squatch/widget.py`. That assertion means the file pins two things in the same drain: the findings-fed re-offer, and the report line printed when that admission triggers the engine-plane handoff. Moving the widget to `src/widget.py` would drop that assertion. Keeping the coverage would then need a second fixture or a second test path for the self-upgrade case, which D10 and the no-dual-path rule weigh against. The stub does not weaken the re-entry claims. Every prior-attempts, criteria-position and ticket-untouched assertion (lines 174-226) is checked against the fake agent's request log and the git history, and the `uv` stub cannot change either one. The message reports no flake, no false pass and no misleading failure. It has no evidence and comes from `bootstrap-ingest`, so under D10 the change would be speculative. A tombstone does not fit. decisions 000203, 000204, 000208 and 000209 cover the handoff's deadline, tally, stdin and env. decision-000197 covers the on-disk spool proof for the re-entry prompt. shakeout-drain covers the drain's own re-offer. None of them covers where this fixture puts its file. Reopen if a re-entry test fails or passes falsely because of the self-upgrade path or the `NoHandoff` stub, if the handoff's report line gets its own dedicated test so line 228 is no longer the only place it is pinned, or if this file is restructured for another reason, when the host-shaped path could be adopted in the same change.
