No action. This message is a bootstrap-ingest note, and it proposes no work. It only records a design split that the merged code already follows. `load(path: Path | None = None, *, cwd: Path)` in squatch/config.py:300 takes the resolved `--config` value and holds no cache: there is no module-level cache or lru_cache in squatch/. The Phase 1 CLI owns the argparse wiring. `_config(args, cwd)` in squatch/__main__.py:722-726 calls `load(args.config, cwd=cwd)` and turns a `ConfigError` into a `Refusal`. The per-cycle re-parse the message expects has also been built. The writer-verb composition defines `config_supplier()` as a fresh `_config(args, cwd)` call (__main__.py:645-646) and passes it to the daemon control factory (__main__.py:384, 423, 459). The daemon dispatch boundary then calls `snapshot(self._config_supplier())` for each admitted dispatch (daemon.py:231). That call re-reads config.yaml and deep-copies the result (config.py:224-226). The merged `dispatch-config-snapshot` probably delivered this. Its Goal line names only the isolated per-dispatch value, though, not the re-parse, so a tombstone against it would mean guessing the link. This matches decision-000018 for a sibling deliverable-5 note. Adding a cache in `load`, or a second reload path, would be a dual path that no incident has earned, which the no-dual-path and anti-bloat laws rule out. No open ticket or decision covers config load caching or re-parse cadence. The open `config-gate-code-vocab` and `host-contract-null-rule` cover validation content, not load cadence. Reopen if a ticket adds caching to `config.load`, or if a long-running verb is found using a config value loaded once at startup where a per-dispatch value is required.

Evidence: squatch/config.py:300 `def load(path: Path | None = None, *, cwd: Path) -> Config` (no cache anywhere in squatch/); squatch/__main__.py:722-726 `_config` -> `load(args.config, cwd=cwd)`; __main__.py:645-646 `config_supplier` re-calls `_config`; __main__.py:384 passes `config_supplier=lambda: _config(args, cwd)` to the control/daemon composition; squatch/daemon.py:231 `config = snapshot(self._config_supplier())` per admitted dispatch; config.py:224-226 `snapshot` deep-copies. Merged: dispatch-config-snapshot.
