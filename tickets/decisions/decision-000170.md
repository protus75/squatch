No ticket. The facts in the message are right, but the two wordings belong to two different situations, so merging them would remove information the operator needs. (1) Inside the pipeline: `Runner.dispatch` (squatch/runner.py:365) journals `running` for a run_seq before `pipeline.run`. Any exception there, `GitError` included, goes to `_fault` (:376-379, and :451-454 for diagnose/lift). `_fault` logs the traceback to the redacted engine log and returns `Refusal('<stem> run <n> faulted: GitError: ...')`. Its paved road says that run is left `running` with no terminal for reconcile to reap, and to fix the cause and re-run `squatch run <stem>`. tests/test_terminal.py:869 and :952 pin this wording. (2) Outside the pipeline: the `except GitError` in `_locked`'s `go()` (squatch/__main__.py:716-719) catches git failures from session entry, intake, reconcile and similar steps. No run has started at that point, so there is no orphan to report, and the road 'inspect the checkout; the failing argv is in the message' fits. Both paths raise `Refusal`, so `main` prints both the same way (`refused:` / `paved road:`) with the same exit code. The exit code does not differ between them, and nothing in the message shows that it does. Choosing one owner would mean either (a) letting a pipeline `GitError` reach the outer handler, which drops the orphaned-run road and the engine-log traceback, or (b) wrapping non-run git failures as a run fault, which would name a run that does not exist. Both lose accuracy. The fault wording is keyed on 'which run broke'. The exception class is incidental, and every non-Refusal fault class shares that wording. SQUATCH_PLAN.md has no rule requiring one wording per exception class. The message cites no evidence or operator confusion, and Phases 3-6 merged on this behavior, so under D10 the change is speculative. No rendered work or decision covers this. decision-000168 covers redacting `_fault`'s text and decision-000166 covers whether `ExecutableNotFound` should refuse or park, so a tombstone would be wrong. Reopen if the operator adds a single-wording-per-exception-class rule to the plan, if a pipeline `GitError` stops naming its orphaned run, or if an outer `git:` refusal is found while a `running` run exists for that invocation.

Evidence: squatch/runner.py:365-379 (running journaled before the pipeline; any exception goes to _fault); squatch/runner.py:494-506 (_fault wording and orphan road); squatch/__main__.py:716-719 (outer GitError becomes `git:` refusal, no run in flight); tests/test_terminal.py:869,952 (fault wording pinned); no matching rule in SQUATCH_PLAN.md.
