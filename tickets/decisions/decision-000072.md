No action. The message is right about how the code behaves but names the wrong file, and the gap it points at is only plan wording. The stuck-budget kill is not in squatch/driver.py; there is no `_call` there. It is `LLMEffect._call` in squatch/llmeffect.py:59-104. `_within_budget` waits with `asyncio.wait({task}, timeout=...)`, or with a clock-seam deadline and a sleeper raced by `asyncio.wait(FIRST_COMPLETED)` (:74-99). On expiry or outer cancellation, `_abort` calls `abort_current()` first, then `task.cancel()`, then `asyncio.wait({task})` (:101-104). The module docstring (:11-14) gives the reason: `abort_current` must run before anything is recorded, so a resistant writer is dead before its terminal exists. `asyncio.wait_for` and `asyncio.timeout` both cancel the inner task and then wait for it to unwind. That hangs on a callee that resists cancellation, and it offers no hook to run `abort_current` first. So the code's choice is right, and the merged shakeout-driver ticket already pins the timeout kill end to end. What is left is wording. Section 8's watchdog paragraph (SQUATCH_PLAN.md:1156) says 'Per-stage `asyncio.wait_for`', and the shakeout-driver Goal says 'killed by the driver's `wait_for`'. Both name a primitive the code rightly does not use. The code is consistent and nothing is blocked. The risk is a plan regeneration that takes the wording literally and uses `asyncio.wait_for`, which would lose the abort-first order. This is handled the same way as decision-000053, -000062, -000064, -000067 and -000069 for small plan/code wording gaps. A ticket would only restate existing behaviour, which the anti-bloat law rules out. No rendered ticket or decision covers the stuck-budget primitive. seams-kill-transport-timeout covers the subprocess kill path, not the LLM effect's budget, so a tombstone would be wrong. Reopen if a plan regeneration or a new surface builds the stuck budget on `asyncio.wait_for`/`asyncio.timeout`, or if the operator treats the wording as a plan defect. The fix then is to reword SQUATCH_PLAN.md:1156 to say: a per-call stuck budget enforced by bounded `asyncio.wait`, with `abort_current` before task cancellation.

Evidence: squatch/llmeffect.py:11-14 (docstring: abort before record), :59-72 (`_call`), :74-99 (`_within_budget` via asyncio.wait), :101-104 (`_abort`: abort_current, cancel, wait); squatch/driver.py:97-103 (`abort_active` is the kill-verb cancel, not the stuck budget); SQUATCH_PLAN.md:1156 ('Per-stage `asyncio.wait_for`'); merged shakeout-driver Goal ('killed by the driver's `wait_for`').
