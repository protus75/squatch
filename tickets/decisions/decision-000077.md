No action. The gap the message describes is already closed in the merged code and tests. The engine-log writer scrubs before it encodes: `EngineLog.event` (squatch/enginelog.py:30-35) runs `_scrub` over the whole record, including nested keys and values and stringified non-JSON leaves, and only then calls `json.dumps`. A comment at enginelog.py:32-34 explains that order. The message is right that `test_engine_log_writes_one_scrubbed_json_line_per_event` (tests/test_driver.py:181-190) uses an ASCII-safe secret, but that test pins line-per-event shape and ts rendering, not the encoding order. The very next test, `test_engine_log_scrubs_before_json_escaping_rewrites_the_secret` (tests/test_driver.py:193-203), is the requested regression pin. Its secret is 'sk"quo\\back\u00e9uni', with a quote, a backslash and a non-ASCII character. It checks that the secret is absent from the raw line, that the decoded `note`, the nested list value, the nested dict key and a `Path` leaf all come back as `[REDACTED:K]`, and that the secret is absent from a non-ASCII re-encoding of the record. An encode-then-redact writer would fail every one of those decoded assertions. Changing the first test's secret as well would duplicate this pin, which the anti-bloat law rules out. No rendered ticket or decision covers engine-log redaction ordering: the open journal-*, seams-* and config-* tickets cover other things. So a tombstone would be wrong.

Evidence: squatch/enginelog.py:30-35 (scrub-before-dumps, why-comment at :32-34); squatch/enginelog.py:49-61 (`_scrub` recurses over keys, values, sequences and non-JSON leaves); tests/test_driver.py:193-203 (`test_engine_log_scrubs_before_json_escaping_rewrites_the_secret` with a quote/backslash/non-ASCII secret, asserting decoded redaction of note, nested value, nested key and Path leaf); tests/test_driver.py:181-190 (the ASCII-secret test the message names, which pins line shape only). Reopen if the escaping-secret test is removed or weakened, or if a second engine-log writer or encoding path is added without the same pin.
