No action. The gap the message describes was real when Phase 1 was bootstrapped, and the merged code has since closed it using the second option the message offers: the adapter takes the spool root when it is constructed. `CliClient` in squatch/providers.py builds `self._spools = Path(state_dir) / "spools"` at line 397. For each call (lines 433-442) it writes the redacted `req.rendered` to `spools/<ticket-or-surface>/cli/<seq>-<surface>-prompt.md` through the filesystem seam and passes that path as `stdin_path` to process-exec, so the prompt never goes on argv. `LLMRequest` (squatch/llm.py:32-34) carries only `rendered: str`, which matches the fixed shape in section 6 (SQUATCH_PLAN.md:1059-1062). Nothing is blocked and there is no path for the adapter to find. One small mismatch remains between plan and code: SQUATCH_PLAN.md:1016 says the adapter connects THAT FILE, meaning the driver's own spooled `NNN-prompt.md` (driver.py:122). The code instead delivers a second redacted copy written by the adapter. Both files come from the same rendered text, so the prompt the model receives is the one audited, and the difference is only wording. Adding a spool-path field to `LLMRequest` would change a fixed section 6 shape that every surface and adapter uses, to fix something already working, which the anti-bloat and no-dual-path laws rule out. No rendered ticket or decision covers how the cli prompt is delivered. The open seams-* tickets cover kill and timeout behavior, not stdin delivery, so a tombstone would be wrong. Reopen if a plan regeneration builds a cli adapter that cannot locate the driver's spool file, or if the two prompt copies are found to differ (for example, a redaction mismatch). In either case, reword SQUATCH_PLAN.md:1016 to say the adapter spools its own redacted copy under `spools/<stem>/cli/` and connects that file as stdin, which is what the code already does.

Evidence: squatch/providers.py:397 (`self._spools = Path(state_dir) / "spools"`), :433-442 (redacted prompt written to spools/<ticket or surface>/cli/<seq>-<surface>-prompt.md and passed as `stdin_path`); squatch/llm.py:32-34 (`LLMRequest.rendered: str`, no path field); squatch/driver.py:122 (driver spools `NNN-prompt.md` separately); SQUATCH_PLAN.md:1016 ('connecting THAT FILE as its standard input'), :1059-1062 (fixed `LLMRequest` shape), :1286 (process-exec `stdin_path` seam).
