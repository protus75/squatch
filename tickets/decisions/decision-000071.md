No action. The message describes a Phase 0 gap that the merged code has since closed. `stuck_seconds` is no longer a Driver constructor argument without a producer. The stuck budget now lives on `LLMEffect`, which defaults to `None` (unbounded) and enforces the budget with `asyncio.wait`/deadline in squatch/llmeffect.py:41-82. The Driver only reads it back when it reports a timeout (squatch/driver.py:132). Both sources the message names are wired. First, each ticket's `## Time budget` stuck minutes are parsed into `Ticket.stuck_minutes` (tickets.py:137, :484-604). Stages then sets `self._llm.stuck_seconds = ticket.stuck_minutes * 60` for each dispatch (stages.py:670) and uses the same budget for verification timeouts (stages.py:367, :532) and the watchdog (watchdog.py:237). Second, `drain.max_ticket_minutes` (config.py:160) is enforced as a cap: the drain holds any ticket whose stuck budget exceeds it (drain.py:304-321), and merge verification uses it as its timeout (merge.py:753). Surfaces with no ticket get fixed budgets: author.py:161 uses AUTHOR_STUCK_SECONDS and triage.py:199 uses TRIAGE_STUCK_SECONDS. Requisition review inherits the base budget (requisition.py:155). The merged shakeout-driver ticket already pins the kill end to end: a stage past its stuck budget is killed, harvested, and ends in `timeout`. No work remains, and a ticket would only restate existing behaviour. No open ticket or decision covers the stuck-budget wiring itself, so a tombstone would be wrong. Reopen if a dispatch path is found that reaches an `LLMEffect` with `stuck_seconds=None` in production, or if a new ticket-less surface is added without a fixed stuck budget.
