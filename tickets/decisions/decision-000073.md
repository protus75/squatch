No action. The message describes the code correctly, and the problem it raises cannot happen with the current readers. `LocalFilesystem.write` (squatch/seams.py:189-197) creates the parent directories, writes `.<name>.tmp` beside the target, fsyncs it and calls `os.replace`, as the message says. The only code that enumerates a spool directory is `harvest.extract` (squatch/harvest.py:70-79, `spool.rglob("*")`). It runs only after the attempt has reached a terminal state or been reaped as an orphan, so the writer has finished or is dead and no write can be in progress. After a crash, a leftover `.NNN-*.tmp` would be harvested as one more redacted tail with its dot-prefixed name. That is diagnostic material from the crashed attempt, which the harvest wants, and it does not corrupt anything. Nothing else globs spools: status, box, journal, tickets, registry and merge each enumerate their own directories with name filters. Filtering temp names in harvest, or moving temp files out of the target directory, would guard against a reader that does not exist, and the anti-bloat law rules that out. A consumer that reads spools live would be the incident that justifies the change. No rendered ticket or decision covers where the filesystem seam puts its temp files. seams-kill-transport-timeout and seams-kill-poll-flake cover the subprocess kill path, so a tombstone would be wrong. Reopen if a consumer is added that reads or globs a spool while its attempt is still running (a live tail, the watchdog, or a status view of spools), or if a harvested `.tmp` tail is found to mislead a diagnosis. In either case the fix, made together with that consumer, is for the reader to skip names matching `.*.tmp`, or for `write` to put its temp file where the glob cannot see it.

Evidence: squatch/seams.py:186-197 (LocalFilesystem.write: fixed `.<name>.tmp` sibling, fsync, os.replace); squatch/harvest.py:65-79 (the only spool enumerator, `spool.rglob("*")` in post-terminal extract); a repo-wide search for glob/iterdir/rglob in squatch/ finds no other spool reader (status.py:180, journal.py:193, stages.py:858/1167, tickets.py:806, registry.py:63, box.py:220 and merge.py:76 all enumerate non-spool directories).
