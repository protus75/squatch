No ticket. The directive grammar belongs to spec lint, not the plan, and the plan stays at the right level of abstraction. In SQUATCH_PLAN.md, section 8 (line 282) and the untrusted-content rule (line 1119) state the contract: injected content renders only inside the data-block form, and spec lint checks that templates wrap injected content that way. Neither spells out the grammar. That is deliberate: the plan says the data/instruction boundary is a rendering contract that spec lint enforces. The exact grammar is defined in one place, `_DIRECTIVE` in squatch/specs.py:40. It accepts `<<<squatch:data name="<slot>">>>`, with or without the ` optional` suffix. The lint finding's paved road (specs.py:305) names both forms, so an author who gets it wrong is told the correct syntax. The `optional` semantics are documented next to the regex (specs.py:38), and the render-time missing-slot check honours them (specs.py:109-116). Copying the grammar into section 8 or the section 21 appendix would create a second statement of a fact the code already owns, and the two could drift apart; the no-dual-path rule and the plan-is-pure-spec rule both weigh against that. The message's own condition ('if the grammar is meant to be plan-owned') is not met, and the message gives no evidence that anyone authored a spec wrongly because the plan was silent (evidence: None), so under D10 the edit would be speculative. A tombstone does not fit: no rendered open ticket, merged Goal line or decision covers the spec directive grammar. Reopen if the plan adds a rule that spec template grammar must be stated in the plan, if a third directive form is added, or if a spec-authoring failure is traced to the grammar being undocumented in the plan.

Evidence: specs/implement.md:79 carries `<<<squatch:data name="prior_attempts" optional>>>`; squatch/specs.py:38-40 defines `_DIRECTIVE` with the optional suffix; specs.py:305 paved road names both directive forms; SQUATCH_PLAN.md:282 and :1119 describe the data-block form abstractly as a spec-lint-enforced rendering contract.
