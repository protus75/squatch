No action. The message describes the code correctly, but the mismatch cannot happen on any production path, and no incident has come from it. `LLMStage.__post_init__` (squatch/driver.py:52-54) checks only that `name` is in `STAGE_NAMES | SUBSTEP_NAMES`. It does not tie `surface` to `name`. There are seven production constructions, and each one pairs a fixed literal name with the surface of the spec it loads: implement (stages.py:810), review (stages.py:1016), retro (retro.py:124), rework (rework.py:91), author (author.py:103), triage (triage.py:144) and diagnose (diagnose.py:110). The eighth, requisition, sets both fields to `REVIEW_CODE` (requisition.py:143). Each spec's `llm_surface` frontmatter equals its stage name: implement, review, triage, diagnose, retro, rework, author and requisition_review in specs/*.md line 2. So no production stage can spool or route under another stage's identity. The only mismatched builds are test fixtures. tests/test_driver.py:372 and tests/test_llm_effect.py:253 override `surface="triage"` on a default-named stage so they can exercise the ticket-less spool stem (driver.py:112-113). The check would force those fixtures to change and would guard a pairing that production already fixes by construction. The anti-bloat law needs an incident to justify a new check, and none exists here. A pairing rule also needs its own exception list (diagnose, requisition_review, host surfaces), and that list is a second closed vocabulary to keep in sync with `LLM_SURFACES` and the config-extended surface set (see decision-000075). A tombstone would be wrong because no rendered ticket or decision covers the name/surface pairing on `LLMStage`. decision-000075 is about `LLMRequest`'s surface vocabulary for host surfaces, and the open gates-*, config-* and seams-* tickets cover other things.

Evidence: squatch/driver.py:37-54 (LLMStage checks name only); driver.py:112-126 (spool stem and LLMRequest use stage.surface, while the journal records both stage and surface); production constructions at stages.py:810, stages.py:1016, retro.py:124, rework.py:91, author.py:103, triage.py:144, diagnose.py:110 and requisition.py:143 each pair their name with the matching spec surface; specs/*.md llm_surface values equal the stage names; tests/test_driver.py:372 and tests/test_llm_effect.py:253 are the only mismatched builds, and both are test fixtures. Reopen if a production LLMStage is ever built with a surface taken from config or from a spec not fixed to its name, for example when host-review-surface dispatch lands (the decision-000075 trigger). Also reopen if a journal, spool or routing record is found with a stage/surface pair that does not match. The same change should then add the pairing check to LLMStage.__post_init__, with an explicit exception set drawn from the one surface vocabulary, and update the test fixtures.
