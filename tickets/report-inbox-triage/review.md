## Summary
The diff stays inside the fence and the checks are green, but it has two logic defects. A replay file that cannot be read crashes the consumer instead of being rejected, and a report that arrives again under a known signature is dropped without the rereport count that can reopen a tombstone. It is also unclear whether the authored bug ticket itself keeps the evidence.

## Findings
- correctness_review at squatch/inbox.py:111: `self._fs.read(replay_path)` runs outside any `ReportError` conversion. If `stat()` succeeds but the read fails (permission denied, a FIFO, the file removed between stat and read), the resulting `OSError` escapes `consume()`. The report stays as `*.report.json`, so every poll hits the same failure: one bad host arrival becomes a poison pill for the box/inbox consumer. `_metadata` wraps every exception, but the replay read does not. The same applies to `store_evidence`/`enqueue` raising `ValueError`/`BoxCorruption` for one report. (paved road: Wrap the replay read (`OSError`) in `ReportError` so the report is moved to `.rejected`. Isolate any other per-report failure the same way, so one arrival never stops later reports. Add a `tests/test_inbox.py` case with an unreadable replay.)
- correctness_review at squatch/inbox.py:97: When `by_origin(origin)` matches, `_consume_one` returns `True` early and the report is marked `.filed` without calling `Box.enqueue`. `enqueue`'s duplicate path calls `record_rereport`, which counts the arrival and reopens a threshold tombstone. The short-circuit skips that, so repeat host reports of a tombstoned or resolved bug are silently swallowed and never reopen it. `by_origin` matches records of every status, so this covers authored and tombstoned messages too. (paved road: On an origin hit, call `self._box.record_rereport(existing.id)` (idempotence across a crash between enqueue and rename still holds, because a re-run only adds a count). Alternatively, route the duplicate through `enqueue`'s own duplicate path. Add a test that a second report with the same signature increments `reports`.)
- correctness_review at tests/test_triage.py:188: Uncertain acceptance mismatch. The criterion requires triage to author `kind: bug` tickets that retain evidence and `## Regression`. The test checks `kind: bug` and `## Regression` in the authored ticket. For evidence, it checks only that the Box message still holds it and that the replay path appears in the triage prompt. Nothing in `Author` requires, and no test proves, that the authored ticket carries the custody reference (replay path/sha, implicated paths). Once authored, the only link from ticket to evidence is the resolved Box record. (paved road: If 'retaining evidence' means the ticket, have `Author` reject a `bug_report`-sourced ticket that omits the evidence custody reference (for example `evidence.replay_path` in Context or Regression), and assert it in `tests/test_triage.py`. If Box custody is the intended home, cite where the plan says so.)
