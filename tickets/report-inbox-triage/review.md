## Summary
The schema, Box custody and triage/author bug grammar are mostly sound, but four things block the merge. The 1 MiB replay cap only checks the declared size, so the whole file is read before its real size is known. The actual-oversize test never exercises the actual-size check. One bad report stalls triage for good. The new daemon consumer is never called in production.

## Findings
- correctness_review at squatch/inbox.py:90: The scope requires a metadata-first 1 MiB replay cap. `consume` does validate the declared `replay_bytes`, but then calls `self._fs.read(replay_path)` with no bound. A report that declares 2 bytes but points at a multi-GB file makes the engine load all of it into memory before the length comparison. The size is never checked before the read, so the replay read is effectively unbounded. (paved road: Check the file's real size (a stat through the Filesystem seam) against `report.replay_bytes` and REPLAY_LIMIT before reading. Or read at most REPLAY_LIMIT+1 bytes and reject if more came back. Add a test where the declared size is small but the actual file exceeds the limit.)
- correctness_review at squatch/inbox.py:94: `if len(replay) > REPLAY_LIMIT` can never be true. The line above has already required `len(replay) == report.replay_bytes`, and the schema caps `replay_bytes` at REPLAY_LIMIT. `test_actual_oversize_replay_is_refused_before_box_recording` (tests/test_inbox.py) also declares `replay_bytes=REPLAY_LIMIT+1`, so it fails metadata validation and never touches the actual-file cap it is named for. The acceptance criterion that replay files cap at 1 MiB is therefore only proven for the declared value. (paved road: Replace the dead branch with a bounded pre-read check (see the previous finding). In the test, declare a valid `replay_bytes` while the file on disk is larger than REPLAY_LIMIT, and assert the refusal and that the Box stays empty.)
- correctness_review at squatch/daemon.py:400: `inbox_consumer` calls `inbox.consume()` before `triage.run`. `consume` raises ReportError on the first malformed report, and the file stays in the inbox. Every later pass raises again, so Box triage never runs again. One bad host report stalls the whole Suggestion Box queue: a hold with no release path. Relatedly, `Inbox._metadata` silently skips any JSON object without `schema_version`. A report missing that field is ignored forever instead of refused, which is a fail-open path. (paved road: Isolate each report. On ReportError, quarantine or reject that one report (for example move it aside, or file a Box message about the invalid report) and carry on with the others, so `triage.run` always runs. Tell replay files apart from reports by an explicit rule (for example reports only in `*.report.json`, or replay files referenced by a report are excluded) rather than by whether `schema_version` is missing.)
- correctness_review at squatch/daemon.py:397: The scope requires wiring the daemon consumer, but `inbox_consumer` is only defined and tested. Production still calls `box_consumer` in squatch/serve.py (around line 134), and nothing builds an `Inbox` or resolves its directory. Host reports are never ingested by the running daemon. Unsure whether this belongs to the implementer or the ticket: serve.py is outside the scope fence, so the wiring may be unreachable as fenced. (paved road: Wire `inbox_consumer` into the daemon's box loop from inside the fence, for example by having the daemon.py function that the box task calls build and consume the inbox. If that genuinely needs serve.py, return the ticket as `rma` to widen the fence rather than shipping an unwired consumer.)
- correctness_review at squatch/box.py:241: `Box.enqueue` accepts any `Evidence`, including one with `replay_path=""` (the model default) or a path that was never written. For example, tests/test_triage.py enqueues `replay_path="box/evidence/replay.json"`, a file that does not exist. Durable custody is enforced only by `Inbox` calling `store_evidence` first, so any other caller can record a message whose evidence names no custodied bytes. Scope out forbids bypassing Box custody. (paved road: In `enqueue`, when evidence is given, require that `evidence.replay_path` exists under `self.dir / "evidence"` and that its SHA-256 matches `replay_sha256`. Or make `store_evidence` the only way to build custodied evidence, for example by storing and enqueuing in one Box method. Update the triage test to store its evidence through the Box.)
